# ประเมินเว็บไซต์ Profile CV — บันทึกและแผนแก้ไข

ตรวจเมื่อ: 30 ก.ค. 2569
วิธีตรวจ: อ่านโค้ดในโปรเจกต์ + เปิดเว็บทดสอบจริงผ่านเบราว์เซอร์ (จอ 1440px และ 390px) + ทดสอบสลับภาษา TH/EN

สรุป: โครงสร้างเนื้อหาแข็งแรงอยู่แล้ว โดยเฉพาะส่วนประสบการณ์ทำงาน ปัญหาที่พบเป็นเรื่อง "การประกอบร่างทางเทคนิค" มากกว่า "การออกแบบใหม่" ข้อ 1–3 ด้านล่างแก้รวมกันได้ในไม่ถึงครึ่งชั่วโมง และปิดช่องโหว่ที่กระทบเยอะที่สุด (ผู้ใช้มือถือเข้าเมนูไม่ได้) ได้ทันที

---

## 1. บั๊กที่ต้องแก้ก่อน (Critical)

### 1.1 เมนูแฮมเบอร์เกอร์บนมือถือกดไม่ทำงาน
ผู้ใช้มือถือเข้าเมนูนำทางไม่ได้เลย ยืนยันจากการทดสอบจริง (`hasClickHandler: false` บนปุ่ม `.sidebar-toggle`)

**สาเหตุ:** `assets/js/app.js` โหลด HTML ของ header/offcanvas ด้วย `fetch()` แบบ async แต่ `assets/js/main.js:91` รัน `$(".sidebar-toggle").on("click", ...)` ทันทีตอน script โหลด ซึ่งเร็วกว่า fetch จะเติม HTML เข้า DOM เสมอ ผลคือ jQuery ผูก event ให้ element ที่ยังไม่มีอยู่จริง

**วิธีแก้:** ย้ายบรรทัด 87–100 ใน `main.js` เข้าไปในตัว listener `document.addEventListener("componentsLoaded", ...)` ที่มีอยู่แล้ว (บรรทัด 230) หรือเปลี่ยนเป็น delegated event: `$(document).on("click", ".sidebar-toggle", ...)`

**เวลา:** ~5 นาที

## 2. ข้อมูลส่วนตัวที่เปิดเผยเกินจำเป็น (High/Medium)

### 2.1 ที่อยู่บ้านเต็มรูปแบบ ปรากฏซ้ำ 3 จุด
"15/178 หมู่บ้านศิริทรัพย์ ต.บางพูน อ.เมืองปทุมธานี จ.ปทุมธานี 12000" อยู่ใน `offcanvas.html`, `footer-area.html` และหน้า contact — เป็นที่อยู่ระดับบ้านเลขที่

**แนะนำ:** เหลือแค่ระดับอำเภอ/จังหวัด เช่น "ปทุมธานี, ประเทศไทย"

### 2.2 เบอร์โทร/อีเมล plain text ซ้ำ 8+ จุด ไม่มีการป้องกัน bot
**แนะนำ:** พิจารณาใช้แบบฟอร์มติดต่อแทนการโชว์เบอร์ตรงๆ หรือลดจุดที่ซ้ำซ้อนลง

### 2.3 โชว์เกรดเฉลี่ยต่ำ (2.35 / 2.55) แบบไม่มีบริบท
**แนะนำ:** ตัดเกรดเฉลี่ยออกจากส่วนการศึกษา เหลือแค่สถาบัน + สาขา + ช่วงเวลา

**เวลารวมข้อ 2:** ~15 นาที

---

## 3. โครงสร้างเทคนิคที่กระทบการมองเห็น (High/Medium)

### 3.1 ไม่มี Open Graph / Twitter meta tags
แชร์ลิงก์ใน LinkedIn/Facebook/Line แล้วพรีวิวจะไม่มีรูป/คำอธิบาย

**วิธีแก้:** เพิ่ม `og:title`, `og:description`, `og:image` (ใช้รูปโปรไฟล์ที่มีอยู่แล้ว) และ `twitter:card` ใน `index.html`

**เวลา:** ~10 นาที

### 3.2 เนื้อหาทั้งหน้าโหลดผ่าน JS fetch — crawler ที่ไม่รัน JS เห็นหน้าเปล่า
`app.js` โหลด banner, about, experience ฯลฯ ทั้งหมดด้วย `fetch().innerHTML` bot ที่ไม่รอ JS จะเห็น body ว่าง

**แนะนำ:** ใส่เนื้อหาสำคัญ (ชื่อ, ตำแหน่ง, สรุปย่อ) แบบ static ไว้ใน `index.html` โดยตรงเป็น fallback ก่อน JS จะ hydrate ทับ

## 4. UI ที่เจอจากการเปิดเว็บจริง (Medium)

### 4.1 ช่องว่างขนาดใหญ่ผิดปกติ ก่อน section ติดต่อ
หมวด "Cloud & Infrastructure" มีการ์ดใบเดียว ทำให้แถวไม่เต็ม เกิดพื้นที่ว่างสูง ~300–400px

**แนะนำ:** ลด padding ของ section สุดท้ายในกลุ่ม certifications หรือจัด layout ไม่ให้การ์ดเดี่ยวทิ้งพื้นที่ว่างมาก

### 4.2 ข้อความ marquee คอนทราสต์ต่ำมาก อ่านแทบไม่ออก
ตัวอักษรสีเทาเข้มบนพื้นกรมท่าเข้ม (`.rs-text-slide-item`) ทำให้ keyword ดีๆ (Golang, Data Engineering, REST API) จางจนมองไม่เห็น

**แนะนำ:** เพิ่ม opacity/ความสว่างให้ contrast ผ่านมาตรฐาน AA

### 4.3 console error ทุกครั้งที่โหลดหน้า
`assets/js/brithday.js` บรรทัดสุดท้ายมีอักขระ "å" หลงเหลืออยู่หลัง `});` ทำให้เกิด `ReferenceError: å is not defined`

**วิธีแก้:** ลบอักขระ "å" ท้ายไฟล์บรรทัด 21 ออก

**เวลารวมข้อ 4:** ~20 นาที

## 5. โอกาสด้านเนื้อหาที่ยังไม่ได้ใช้

### 5.1 มีภาพหน้าจอผลงานจริง 4 ไฟล์ แต่ไม่ได้ถูกใช้บนเว็บเลย
ใน `assets/images/portfolio/` มี `E-Advce.png`, `E-MM.png`, `E-PR.png`, `HT.png` — ภาพหน้าจอระบบจริงจากงานที่ CloudMate และ NatureBiotech (ตรงกับที่อธิบายในส่วนประสบการณ์) แต่ section `id="homeportfolio"` ถูกเปลี่ยนไปแสดงเฉพาะใบรับรองแทน ไม่มี section "ผลงาน" ที่โชว์ภาพเหล่านี้

**แนะนำ:** เพิ่ม section "ผลงาน" แยกจากใบรับรอง ใช้ภาพ 4 ไฟล์นี้ประกอบคำอธิบายสั้นๆ — เป็นสิ่งที่ recruiter มักมองหาเป็นอันดับต้นๆ และตอนนี้มีวัตถุดิบพร้อมอยู่แล้ว

**เวลา:** ~1–2 ชม.

### 5.2 ไม่มีแบบฟอร์มติดต่อ มีแต่ลิงก์ tel/mailto
มีไฟล์ `assets/mailer.php` อยู่ในโปรเจกต์แล้ว (บ่งชี้ว่าเคยมีแผนทำฟอร์ม) แต่ยังไม่ได้ต่อเข้ากับหน้าเว็บ

**แนะนำ:** ถ้า `mailer.php` ยังใช้งานได้ ให้เพิ่มฟอร์มติดต่อสั้นๆ ใน contact section

## 6. จุดที่ทำได้ดีอยู่แล้ว — ไม่ต้องแตะ

- **ส่วนประสบการณ์ทำงานเขียนละเอียดและน่าเชื่อถือมาก** — แต่ละโปรเจกต์มีทั้ง "หน้าที่" และ "ผลลัพธ์" แยกชัดเจน พร้อม tech stack badge
- **ระบบสองภาษา (TH/EN) ทำงานลื่นไหล** — สลับแล้วเนื้อหาเปลี่ยนถูกต้องทั้งหน้ารวม footer/offcanvas
- **Responsive layout บนมือถือ (ยกเว้นเมนู) จัดวางดี** — banner, skill card, experience accordion อ่านง่ายบนจอ 390px
